# __PROJECT_NAME__

Full-stack application generated by the **Mosaic CLI**:

- **Application** — SvelteKit 5 **PWA** rendering database-first pages and forms
- **API** — Hono mounted at same-origin `/api` inside the SvelteKit deployment
- **Studio** — the visual builder, built into the same app at `/studio`
- **CLI** — `mosaic` for migrations, seeding and scaffolding

## Quick start

```bash
# The CLI already installed dependencies and generated .env.
# If you used --no-install, run npm install first.
npm run dev
```

- App and API: http://localhost:__WEB_PORT__ (`/api` for API routes)
- Studio: http://localhost:__WEB_PORT__/studio (administrators and editors)
- Default admin (when seeded): `admin@mosaic.local` / `admin1234`

Local development defaults to persistent embedded PostgreSQL (`pglite://./data`).
It needs no Docker container or database port. Data is stored in the project's
`data/` directory, shared by the API and CLI. Preserve the generated `.env`;
copying `.env.example` over it replaces your generated secret and configuration.

For external PostgreSQL, set `DATABASE_URL` in `.env` to an existing database.
To use the supplied Docker service instead, set
`DATABASE_URL=postgres://mosaic:mosaic@127.0.0.1:__DB_PORT__/__PROJECT_SLUG__`
and run `npm run db:up` before starting the app. If that port is occupied, set
`MOSAIC_DB_PORT=5433` and change the URL to use `5433`. Do not stop an unrelated
database to free its port. `db:down` stops the container and preserves its data.

If the app port is occupied, stop your other app or set `MOSAIC_WEB_PORT` in `.env`
to an available port. The launcher checks the port before booting and stops its
child process when the app fails. Restart the command after changing `.env`.

## Model → migrate → CRUD loop

Entities are TypeScript classes in `apps/web/src/lib/server/entities/*.entity.ts`:

```ts
import { Entity, Field, Relation } from '@mosaic-apps/core';

@Entity({ name: 'invoice', label: 'Invoice', softDelete: true })
export class Invoice {
  @Field({ type: 'string', required: true, searchable: true, maxLength: 160 })
  number!: string;

  @Field({ type: 'enum', options: ['draft', 'sent', 'paid'], default: 'draft' })
  status!: string;

  @Field({ type: 'decimal', precision: 14, scale: 2, min: 0, default: 0 })
  total!: number;

  @Relation({ entity: () => Customer, required: true })
  customer!: string;
}
```

1. Add a class (or run `mosaic entity Invoice --fields "number:string,total:decimal"`).
2. `npm run migrate` — plans SQL (dry-run preview) then applies it.
3. Instant CRUD: `GET/POST/PATCH/DELETE /api/entities/<name>` (+ `/meta`, `/options`).

`*.entity.json` files still work; a class wins when both declare the same entity.

## Design forms & pages

Open **Mosaic Studio** at http://localhost:__WEB_PORT__/studio and choose components from the palette.
Pages and forms are stored in PostgreSQL; users edit them visually rather than editing
JSON. Published pages resolve at their configured route, including `/` and arbitrary
nested or parameterized routes such as `/customers/:id`. The seeded `/404` page is
editable, and page settings can require login. Concrete SvelteKit route files override
database routes.

Studio's source lives in `apps/web/src/routes/studio` and `apps/web/src/lib/studio`.
For package-backed visual components, install the package in `apps/web` and call
`registerComponent` from `apps/web/src/lib/mosaic-components.ts`; the app and Studio
share that registration. The generated agent skill contains the same takeover guidance.

## PWA

The web app is installable (manifest + service worker). Its shell and static assets
can be cached; private API records and uploads are not cached. Record operations
require network access; offline writes and synchronization are not implemented.

## CLI

```bash
mosaic entity Product --fields "name:string,price:decimal,stock:int"  # scaffold entity class
mosaic migrate              # plan + apply migrations
mosaic seed --demo          # seed demo data
mosaic dev                  # run the app, /api and /studio
mosaic studio               # same as dev; Studio is at /studio
mosaic info                 # show project info
```

## Deploy

Deploy one application project after provisioning PostgreSQL.

1. Create or connect Neon, Supabase, or compatible PostgreSQL.
2. Run `npm run migrate` against the production `DATABASE_URL`.
3. Set `DATABASE_URL`, a stable `MOSAIC_JWT_SECRET` of at least 32 characters,
   `SEED=false`, and `SEED_DEMO=false` in the host. On serverless hosts, start with
   `MOSAIC_DB_POOL_MAX=2` and increase it only within the database connection budget.
4. Set the project root to `apps/web`, build with `npm run build`, and deploy.

For Vercel set `MOSAIC_DEPLOY_TARGET=vercel`; for Netlify use `netlify`. UI and
API share one origin, so `PUBLIC_API_URL` and CORS configuration are unnecessary.
Studio ships inside the same deployment at `/studio`, gated by sign-in (administrators
and editors); there is no second deployment.
Serverless filesystems are ephemeral: connect object storage for uploads rather
than relying on `UPLOADS_DIR`.
