# __PROJECT_NAME__

Full-stack application generated by the **Mosaic CLI**:

- **API** — Hono + PostgreSQL with metadata-driven entities, auto migrations and auto-generated CRUD
- **Web** — SvelteKit 5 **PWA** rendering your published forms (JSON) and pages
- **CLI** — `mosaic` for migrations, seeding and scaffolding

## Quick start

```bash
# The CLI already installed dependencies and generated .env.
# If you used --no-install, run npm install first.
npm run dev
```

- API: http://localhost:__API_PORT__
- Web: http://localhost:__WEB_PORT__
- Studio: http://localhost:__STUDIO_PORT__
- Default admin (when seeded): `admin@mosaic.local` / `admin1234`

Local development defaults to persistent embedded PostgreSQL (`pglite://./data`).
It needs no Docker container or database port. Data is stored in the project's
`data/` directory, shared by the API and CLI. Preserve the generated `.env`;
copying `.env.example` over it replaces your generated secret and configuration.

For external PostgreSQL, set `DATABASE_URL` in `.env` to an existing database.
To use the supplied Docker service instead, set
`DATABASE_URL=postgres://mosaic:mosaic@127.0.0.1:__DB_PORT__/__PROJECT_SLUG__`
and run `npm run db:up` before starting the app. If that port is occupied, set
`MOSAIC_DB_PORT=5433` and change the URL to use `5433`. Do not stop an unrelated
database to free its port. `db:down` stops the container and preserves its data.

If an app port is occupied, stop your other app or set `PORT` (API),
`MOSAIC_WEB_PORT`, and `MOSAIC_STUDIO_PORT` in `.env` to distinct available ports.
The launcher checks all ports before booting and stops its child processes when
any service fails. Restart the command after changing `.env`.

## Model → migrate → CRUD loop

Entities are TypeScript classes in `apps/api/src/entities/*.entity.ts`:

```ts
import { Entity, Field, Relation } from '@mosaic-apps/core';

@Entity({ name: 'invoice', label: 'Invoice', softDelete: true })
export class Invoice {
  @Field({ type: 'string', required: true, searchable: true, maxLength: 160 })
  number!: string;

  @Field({ type: 'enum', options: ['draft', 'sent', 'paid'], default: 'draft' })
  status!: string;

  @Field({ type: 'decimal', precision: 14, scale: 2, min: 0, default: 0 })
  total!: number;

  @Relation({ entity: () => Customer, required: true })
  customer!: string;
}
```

1. Add a class (or run `mosaic entity Invoice --fields "number:string,total:decimal"`).
2. `npm run migrate` — plans SQL (dry-run preview) then applies it.
3. Instant CRUD: `GET/POST/PATCH/DELETE /api/entities/<name>` (+ `/meta`, `/options`).

`*.entity.json` files still work; a class wins when both declare the same entity.

## Design forms & pages

Open **Mosaic Studio** at http://localhost:__STUDIO_PORT__ and choose components from the palette.
Forms/pages are stored as JSON in `mosaic_forms` / `mosaic_pages`; publish, then visit
`/f/<form-slug>` or `/p/<page-slug>` in the web app.

## PWA

The web app is installable (manifest + service worker). Its shell and static assets
can be cached; private API records and uploads are not cached. Record operations
require network access; offline writes and synchronization are not implemented.

## CLI

```bash
mosaic entity Product --fields "name:string,price:decimal,stock:int"  # scaffold entity class
mosaic migrate              # plan + apply migrations
mosaic seed --demo          # seed demo data
mosaic dev                  # run API + web together
mosaic studio               # open the drag & drop studio
mosaic info                 # show project info
```

## Deploy

Deploy PostgreSQL first, then the API, then the web app.

1. Set the API's `DATABASE_URL`, `MOSAIC_JWT_SECRET`, `CORS_ORIGINS`,
   `SEED=false`, and `SEED_DEMO=false`.
2. Build the API with `npm --prefix apps/api run build`, run
   `npm run migrate`, then start it with `npm --prefix apps/api run start`.
3. Set the web build's `PUBLIC_API_URL` to the public API URL including `/api`.
4. Build and start the Node web service with `npm --prefix apps/web run build`
   and `npm --prefix apps/web run start`.

For Netlify, set `MOSAIC_DEPLOY_TARGET=netlify` during the web build. For Docker
or Vercel, set `MOSAIC_DEPLOY_TARGET` on both the web and Studio builds. Both
frontends use `PUBLIC_API_URL` including `/api`. For a Node host, Studio starts
with `npm run start -w apps/studio`. For Docker or Fly.io, use `Dockerfile.api`,
`Dockerfile.web` and `Dockerfile.studio`. Keep `UPLOADS_DIR` on a
persistent disk when file uploads are enabled. The Mosaic Deployment guide
covers Vercel + Neon, Netlify, Render, Supabase, Railway, Fly.io and containers.

For the API on Vercel, use `apps/api` as the project root and its native Hono
`app.ts` entry with the supplied `vercel.json`. Configure a persistent PostgreSQL
URL and stable JWT secret, then migrate and seed the database before deployment.
The serverless entry disables disk uploads; use a persistent API host when
built-in image, logo or file uploads are required.
